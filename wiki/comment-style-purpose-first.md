## 증상

orchestrator가 developer 위임 프롬프트에 **직접 써 넣은** 주석이 사용자에게 연속 반려됐다.

- `MonitorMain` 호출부 — 실행문 **2줄** 위에 주석 **7줄** → *"주석이 너무 많아서 뭔지 모르겠어"*
- `attachdownloadlog.jsp` — 코드 **2줄** 위에 주석 **12줄** → *"이걸 근데 이렇게 복잡하게 쓸 필요 있어? 결국은 뭐에 사용한다는 거야? 목적이 중요할거 같은데"*

용어도 연달아 걸렸다. `수평 스코프` → *"이게 무슨 의미야?"*, 대안으로 낸 `토글` → *"토글한다는게 무슨 의미야??"*. **작성자에게 자명한 단어가 독자에게 자명하지 않다.**

## 진짜 원인

주석을 **줄 단위로 방어**했다. "이 줄은 남길 이유가 있다"를 하나씩 따지니 각 줄은 정당한데 **총량이 안 줄었다.** 물어야 할 질문은 **"읽는 사람이 뭘 알아야 하나"**였다.

내용의 출처도 문제였다. 계획서 조항(`흐름 0`·`금지 27`·`S-2`·`R-3`)이 구현 주석으로 그대로 흘러 들어왔다 — 계획 단계 산출을 주석으로 옮기는 과정에서 **기계적으로 딸려온 것**이다.

## 회피

호출부 주석은 **"이 값이 뭔가 → 화면에서 뭘로 보이나"** 순. 독자는 **그 메서드를 안 열어볼 사람**이다.

    // 도메인별 첨부파일 다운로드 이력 사용 여부 값.
    // 사용 안 하는 도메인은 화면 진입부터 툴바에 이 문구가 뜬다(AttachDownLoadLog.logDisabledLabel) :
    // "로그 미사용 : 이 도메인은 현재 다운로드 이력을 남기지 않습니다."

빼야 할 것:

- **용어 던지기** — `수평 스코프` `고지` `토글` `fail-closed` `-1은 미상`. 용어 + 즉시 풀이는 괜찮다. **용어만** 던지면 안 된다.
- **계획서 조항번호** — 계획서는 머지 후 사라지고 번호는 밀린다. 근거가 필요하면 **내용을 한 줄로**.
- **javadoc 중복** — 호출부는 "무슨 값이고 어디 쓰이나"까지. "왜 그렇게 계산하나"는 javadoc 몫. 양쪽에 두면 **한쪽만 고쳐져 어긋난다**.
- **일어나지 않은 미래 대비** — *"다른 핸들러가 이 뷰를 재사용하면"* 류. 그런 일이 생기면 화면이 **그 자리에서 깨진다**. 조용히 잘못되는 게 아니면 주석으로 막을 값어치가 낮다.
- **죽은 코드 경고** — 실사용 0건인 키를 "주의하라"고 적으면 **주석이 그 키의 수명을 늘린다**. 실측: 그 키 등장 2건 중 **하나가 그 경고 주석 자신**이었다.

## 화면 문구 인용 — 테스트로 잠겼을 때만

주석에 실제 UI 문구를 인용하면 구체성이 크게 오른다(*"툴바 경고"*라고만 쓰면 뭐가 뜨는지 모른다). 다만 인용문은 **사본**이라 원본(properties)과 조용히 어긋난다.

→ 그 문구를 **verbatim으로 단언하는 테스트가 있을 때만** 인용한다. 없으면 메시지 코드만 적는다. 인용할 때도 코드를 함께 적어 정본 위치를 남긴다.

## 인용한 값을 바꿀 때는 옛 값 전수 grep

같은 세션 실측: 상수를 92일 → 93일로 올렸는데 다른 메서드 주석에 `// 92일 상한에 걸려…`가 하나 남았다. developer가 범위 밖으로 신고했고 orchestrator가 전수 grep을 돌려서야 확정했다. orchestrator의 *"다지점 갱신은 기억으로 완료 판정하지 않는다"* 규칙이 **주석에도 적용**된다.

## 이 지식이 사는 곳 (휘발성 주의)

프로젝트 rules(`.claude/rules/`)와 agent-memory는 **둘 다 gitignore**라 디스크가 날아가면 같이 날아간다([[claude-rules-gitignore-local-only]]). 그래서 이 페이지가 필요하다. 실행 강제는 `agents/developer/developer-*.md ## 주석 작성 관례`(v5.10.0)가 맡고, 이 페이지는 **왜 그런지**를 보관한다.

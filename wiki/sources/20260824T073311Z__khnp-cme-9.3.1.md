## 후보 2 [HIGH] 승인 문서가 단언하는 "외부 사실"을 실측 없이 권위로 채택 → 올바른 값을 뒤집음

**증상**
`/review`의 code-reviewer가 게이트 설정 불일치를 발견하고 *"어느 쪽이 맞는지 **미확정** — 오케스트레이터/기획 측 확인 필요"* 로 **정직하게** 남겼다.
orchestrator가 계획서(`J-J` / `DR-1` / L1851)를 근거로 *"꺼진 쪽이 맞다"* 고 판정하고, developer가 넣은 올바른 값(`use=true`)을 `false`로 **뒤집었다**(F2).
계획서의 근거는 *"이 브랜치는 master로 머지되며 이 파일이 **타 고객사에도 나간다**"* 였는데, 사용자 지적 후 실측하니 **거짓**이었다:
- `git remote` = `http://10.1.1.10:9090/crinity/**customers/khnp**/cme-9.3.1` (고객사 전용 repo, `products` 아님)
- `git show master:...config.xml` 에 `khnp.co.kr` **7회** 하드코딩(`secondaryKey`/`adminInfo`/`recipients`/`replyInfo`/`<khnp>` 블록)

**비용**: F2 위임 + (같은 전제 위의) F7 위임 + F8 전면 되돌리기 = **3라운드**. 더해 승인 설계 번복에 따른 계획서 정정 **7건**(`J-J`/`DR-1`/L339/L1851/L2608/L105/L1313) 발생.

**추정 원인**
`## 사용자 의사결정 요청 형식` 머리에 이런 조항이 있다:
> 승인 문서(ADR/계획)를 근거로 옵션을 낼 때, 그 문서 **내부 모순**을 먼저 확인한다. "ADR이 X라 했으니 X"는 근거가 아니라 검증 대상이다.

그러나 이 조항은 **문서 내부 정합**만 다룬다. 이번에 틀린 것은 문서가 주장하는 **외부 사실**(머지 대상·repo 성격·배포 경로)이었다.
`§0④ 데이터 전제 검증`도 문면이 *"픽스·구현의 correctness가 외부·런타임 데이터에 의존하면"* 이라 **"계획서 서술의 사실 검증"** 으로는 안 읽힌다.
즉 두 규칙 사이에 **"승인 문서가 단언하는 형상 사실"** 축이 비어 있었다.

**제안 개선 방향**
`§0④`에 축 하나 추가:
> **승인 문서가 단언하는 배포·형상 사실**(머지 대상 브랜치, repo 성격/소유, 배포 경로, 고객사 범위, 파일이 어디까지 나가는지)이 **설계 결정의 근거로 인용될 때**는 문서가 아니라 **실측으로 확인**한다 — `git remote -v`, `git show <base>:<path>`, `.git/info/exclude`. 비용은 1~2 커맨드, 안 하면 승인 설계 번복 라운드.

강화 지점: 서브에이전트가 **"미확정"으로 남긴 항목**을 orchestrator가 판정할 때는, 판정 근거가 **문서면 실측을 1회 덧대고**, 실측이 불가하면 사용자에게 올린다.

**근거**
- 이번 세션 F2→F8 3라운드
- 실측 커맨드 2개(`git remote -v`, `git show master:...`)로 즉시 판명됐다

## wiki 기록 후보 (별도 — 하네스 규칙이 아니라 프로젝트 운영지식)

이 세션에서 알아낸 비자명 사실. `/harness-retro` 드레인 시 wiki 페이지 후보로 분리 검토 요망.

1. **신규 팝업 컨테이너는 `consolemf.css` ID 화이트리스트에 없으면 조용히 샌다** — `#editPopup,#pcardDetailPopup,#userDetailPopup` 만 전역 숨김. 신규 팝업 ID는 화면 전용 CSS에 `display:none;position:absolute;left:0;top:0;width:100%;height:100%;overflow:hidden` 을 직접 넣어야 한다. `cr.popup.open()`은 `display:block`, `close()`는 `orgDisplay` 복원이라 **열기 전 숨김은 CSS 책임**.
2. **`@{}` 클라이언트 바인딩은 HTML 이스케이프를 하지 않는다** — `CrConditionManager.convertScriptVariable`이 스크립트 변수 참조로 치환하고, `tocFramework/.../webcmp/` 전체에 `escapeHtml`/`StringEscapeUtils`/`escapeXml` **0 파일**, `CrLibGrid.js`는 `innerHTML` 9곳·escape 0곳. **`@{}` 사용 화면 43개**이고 그중 `monitor/mailmonitoring/mailmonitoring.jsp:150`은 `@{r.subject}`(=외부 발신자가 정하는 메일 제목)를 그대로 표시한다 → **제품 전역 stored XSS 후보, 별도 WI 권장**. (`⚠ 미검증 전제 — 소스 Read. 확정하려면 브라우저 실측 1회`)
3. **Jackson `FAIL_ON_UNKNOWN_PROPERTIES` 기본 활성** — `ConfigUtil:45-54`의 `XmlMapper`가 이 옵션을 끄지 않는다. 설정 POJO에 없는 요소가 `conf/**.xml` 에 있으면 **기동 실패**. POJO↔XML 쌍 변경 시 양쪽 동시 필수(tocProcess rules 안티패턴 #12의 근거).
4. **git-bash에서 PATH는 `/c/...` POSIX 스타일 필수** — `C:/...` 형식은 `which` 해석에 실패해 `mvn`을 못 찾는다.
5. **`docs/*` + `.claude/` 가 `.git/info/exclude` 대상** — feature 문서가 git 미추적이라 **파괴 시 복구 불가**. 이번 사이클에 RESUME이 실제로 1회 0바이트 파괴됐다(git으로 못 되살려 컨텍스트에서 재구성).

# 개선 후보 — 주석 작성 관례를 agent md 로 승격

## 배경

WI 10(첨부파일 다운로드 이력) 작업 중 사용자가 구현 코드 주석을 하나씩 검토하다가,
**"주석이 사람이 보기 애매하다"** 는 지적에서 출발해 관례가 정리됐다.

문제가 된 실제 주석(내가 앞선 라운드에 developer 에게 지시해 넣은 것):

```java
// 도메인별 "첨부파일 다운로드 로그 사용" 플래그.
// 소스는 바로 위 setInnerPageData 가 채운 "domains"(= PageConfig:72 domainDao.getServiceDomain() 결과)다.
// 흐름 0 에서 그 statement 에 attachDownLoadLogFlag 컬럼을 넣었으므로 추가 조회가 없다.
// 수평 스코프(도메인관리자에게 타 도메인 감사설정 비트를 주지 않는다)는 컨트롤러가 아니라
// resolveAttachDownLoadLogFlagJson 이 소스 statement 를 바꾸는 방식으로 강제한다.
// 정적 빌더를 직접 호출하면 그 가드를 통째로 우회한다(금지 27).
// 이 클래스는 매니저와 다른 패키지라 package-private 빌더가 애초에 보이지도 않는다.
```

두 문장 앞에 7줄이 붙어 있었다. 사용자 반응: *"주석이 너무 많아서 뭔지 모르겠어"*.

최종 형태:

```java
// 도메인별 첨부파일 다운로드 이력 사용 여부 값.
// 사용 안 하는 도메인은 화면 진입부터 툴바에 이 문구가 뜬다(AttachDownLoadLog.logDisabledLabel) :
// "로그 미사용 : 이 도메인은 현재 다운로드 이력을 남기지 않습니다."
```

## 후보 — developer-* agent md 에 넣을 일반 원칙

프로젝트 무관하게 성립하는 부분만 추린 것이다. (프로젝트 특수 예시는 해당 프로젝트 rules 에 남김)

### 1. 호출부 주석은 "값의 정체 → 화면에서 뭘로 보이나" 순

호출부 주석의 독자는 **그 메서드를 안 열어볼 사람**이다. 내부 메커니즘이 아니라
반환값의 정체와 그 값이 사용자 화면에서 만드는 결과를 적는다.

### 2. 용어 던지기 금지

읽는 사람이 그 단어를 이미 알아야 이해되는 주석은 설명이 아니다.

- `수평 스코프` · `고지` · `토글` · `fail-closed` · `-1 은 미상`
- → 화면에서 벌어지는 일로 바꿔 쓴다

실제 대화에서 사용자가 `수평 스코프`, 이어서 내가 대안으로 낸 `토글`까지 연달아
*"이게 무슨 의미야?"* 로 되물었다. 작성자에게 자명한 단어가 독자에게 자명하지 않다.

### 3. 계획서 내부 참조 금지

`흐름 0` · `금지 27` · `S-2` · `R-4` · `L1365` 처럼 **저장소 밖 문서의 조항 번호**를
주석에 남기지 않는다. 계획서는 머지 후 사라지거나 번호가 밀리고, 6개월 뒤 그 파일만
읽는 사람은 찾을 방법이 없다. 근거가 필요하면 내용을 한 줄로 요약한다.

### 4. javadoc 내용을 호출부에 복사하지 않는다

호출부는 "무슨 값이고 어디 쓰이나"까지. "왜 그렇게 계산하나"는 그 메서드 javadoc 이 맡는다.
양쪽에 두면 한쪽만 고쳐져 어긋난다.

### 5. 화면 문구 인용은 "테스트로 잠겼을 때만"

주석에 실제 UI 문구를 인용하면 구체성이 크게 오르지만, 인용문은 **사본**이라
원본(properties 등)과 조용히 어긋날 수 있다.

→ **그 문구를 verbatim 으로 단언하는 테스트가 있을 때만 인용한다.** 잠금이 없으면
메시지 코드만 적는다. 인용할 때도 메시지 코드를 함께 적어 정본 위치를 남긴다.

이 프로젝트에서는 `AttachDownLoadLogMessagePropertiesTest.TC-D-04` 가
`logDisabledLabel` 값을 verbatim 단언해 잠가 두고 있어 인용이 안전했다.

### 6. 주석에 인용한 숫자·문구를 바꿀 때 옛 값 전수 grep

이번 세션 실측 사례: `MAX_SEARCH_PERIOD_MILLIS` 를 92일 → 93일로 올렸을 때
`buildAuditDetail` 주석의 `// 92일 상한에 걸려 잘렸을 때...` 하나가 남았다.
developer 가 범위 밖으로 신고했고, orchestrator 가 전수 grep 을 돌려서야 확정했다.

(orchestrator.md 에 이미 "다지점 갱신은 기억으로 완료 판정하지 않는다 — 옛 값 전수 grep"
규칙이 있다. developer 쪽에도 짝이 필요하다는 신호.)

## 왜 rules 가 아니라 agent md 인가

`.claude/rules/` 는 **이중 gitignore** 로 어느 git 이력에도 안 남는다
(제품 repo `.gitignore` 에 `.claude/`, harness repo `.gitignore:2` 에 `rules/`).
이미 wiki `claude-rules-gitignore-local-only.md` 에 문서화돼 있다.

이번 세션에서 이 관례를 `.claude/rules/package/tocAdminServer/backend.md` 의
`## 주석 작성 관례` 절 + 안티패턴 15번으로 넣어 뒀지만, **이 PC 의 이 프로젝트에만** 적용된다.
1~6번은 프로젝트 무관한 일반 원칙이라 developer agent md 가 제자리다.

## 부수 관찰 (판단 재료)

- 이 세션에서 orchestrator 가 developer 에게 넣으라고 지시한 주석이 곧바로 사용자에게
  반려됐다. 즉 **orchestrator 의 주석 지시 자체가 위 원칙을 안 지키고 있었다.**
  developer md 뿐 아니라 orchestrator 가 위임 프롬프트에 주석 문안을 직접 써 줄 때도
  같은 기준이 걸려야 한다.
- 이번에 제거한 `흐름 0` / `금지 27` 은 전부 **계획서 조항 번호**였다. 계획 단계 산출을
  구현 주석으로 옮기는 과정에서 기계적으로 딸려 들어온 것으로 보인다.

```markdown
## 증상

orchestrator 가 developer 위임 프롬프트에 직접 써 넣은 주석이 사용자에게 연속 반려됐다.

- `MonitorMain` 호출부 : 실행문 2줄 위에 주석 7줄 → *"주석이 너무 많아서 뭔지 모르겠어"*
- `attachdownloadlog.jsp` : 코드 2줄 위에 주석 12줄 → *"이걸 근데 이렇게 복잡하게 쓸 필요 있어?
  결국은 뭐에 사용한다는 거야? 목적이 중요할거 같은데"*

용어도 연달아 걸렸다. `수평 스코프` → *"이게 무슨 의미야?"*, 대안으로 낸 `토글` → *"토글한다는게
무슨 의미야??"*. **작성자에게 자명한 단어가 독자에게 자명하지 않다.**

## 진짜 원인

주석을 **줄 단위로 방어**했다. "이 줄은 남길 이유가 있다"를 하나씩 따지니 각 줄은 정당한데 총량이
안 줄었다. 물어야 할 질문은 **"읽는 사람이 뭘 알아야 하나"** 였다.

내용의 출처도 문제였다. 계획서 조항(`흐름 0`, `금지 27`, `S-2`, `R-3`)이 구현 주석으로 그대로 흘러
들어왔다. 계획 단계 산출을 주석으로 옮기는 과정에서 기계적으로 딸려온 것이다.

## 회피

호출부 주석은 **"이 값이 뭔가 → 화면에서 뭘로 보이나"** 순. 독자는 그 메서드를 안 열어볼 사람이다.

    // 도메인별 첨부파일 다운로드 이력 사용 여부 값.
    // 사용 안 하는 도메인은 화면 진입부터 툴바에 이 문구가 뜬다(AttachDownLoadLog.logDisabledLabel) :
    // "로그 미사용 : 이 도메인은 현재 다운로드 이력을 남기지 않습니다."

빼야 할 것:

- **용어 던지기** — `수평 스코프` `고지` `토글` `fail-closed` `-1 은 미상`.
  용어 + 즉시 풀이는 괜찮다. 용어만 던지면 안 된다.
- **계획서 조항번호** — 계획서는 머지 후 사라지고 번호는 밀린다. 근거가 필요하면 내용을 한 줄로.
- **javadoc 중복** — 호출부는 "무슨 값이고 어디 쓰이나"까지. "왜 그렇게 계산하나"는 javadoc 몫.
  양쪽에 두면 한쪽만 고쳐져 어긋난다.
- **일어나지 않은 미래 대비** — "다른 핸들러가 이 뷰를 재사용하면" 류. 그런 일이 생기면 화면이
  그 자리에서 깨진다. 조용히 잘못되는 게 아니면 주석으로 막을 값어치가 낮다.
- **죽은 코드 경고** — 실사용 0건인 키를 "주의하라"고 적으면 주석이 그 키의 수명을 늘린다.
  실측 사례: `attachDownLogFlag` 등장 2건 중 하나가 그 경고 주석 자신이었다.

## 화면 문구 인용 — 테스트로 잠겼을 때만

주석에 실제 UI 문구를 인용하면 구체성이 크게 오른다. *"툴바 경고"* 라고만 쓰면 뭐가 뜨는지 모른다.

다만 인용문은 **사본**이라 원본(properties)과 조용히 어긋날 수 있다.
→ **그 문구를 verbatim 으로 단언하는 테스트가 있을 때만 인용한다.** 없으면 메시지 코드만 적는다.
인용할 때도 코드를 함께 적어 정본 위치를 남긴다.

## 인용한 값을 바꿀 때는 옛 값 전수 grep

같은 세션 실측: 상수를 92일 → 93일로 올렸는데 다른 메서드 주석에 `// 92일 상한에 걸려...` 가
하나 남았다. developer 가 범위 밖으로 신고했고 orchestrator 가 전수 grep 을 돌려서야 확정했다.
orchestrator.md 의 "다지점 갱신은 기억으로 완료 판정하지 않는다" 규칙이 주석에도 적용된다.

## 이 지식이 사는 곳 (휘발성 주의)

프로젝트 rules(`.claude/rules/`)와 agent-memory 는 **둘 다 gitignore** 라 디스크가 날아가면
같이 날아간다([[claude-rules-gitignore-local-only]]). 그래서 이 페이지가 필요하다.
```

> **자원 경합은 층이 있다** — 파일(워크트리로 해결) < 빌드 산출(워크트리로 해결) < **공유 상태 저장소(워크트리로 해결 불가)**.
> 아래 두 사례가 세 번째 층이다. 워크트리는 **파일시스템만** 나눈다.

---

## 사례 1 — 공유 테스트 DB (`@ResourceLock`은 프로세스 간 무효)

**증상:** 테스트를 병렬로 돌리면 `DuplicateKeyException`·MockMvc 빈 누락 등 **산발적이고 재현이 불안정한** DB 오염이 난다. 단독 실행에선 안 난다.

**진짜 원인:** JUnit5 `@ResourceLock`·`SAME_THREAD`는 **한 JVM 안의 스레드 조정 장치**다. mvn 프로세스를 2개 띄우면 **프로세스 간에는 아무 효력이 없다**. 테스트 DB가 하나뿐이면 두 프로세스가 같은 테이블을 동시에 쓴다.

**회피:**
- **순차 실행만이 답이다.** 같은 모듈·같은 DB를 쓰는 테스트 배치는 병렬 발사하지 않는다.
- ⚠ **워크트리 분리로도 안 풀린다.** 빌드 산출 디렉터리(`target/`) 경합에는 워크트리가 답이 되지만 **공유 DB에는 무효**다.
- 판정 순서: 병렬 발사 전 자가체크에서 자원 축을 볼 때 **"공유 DB인가"를 `target/`·포트·락파일보다 위에** 둔다(해법이 더 좁기 때문).

---

## 사례 2 — 공유 `~/.m2` 로컬 저장소 (동일 GAV install은 마지막에 쓴 쪽이 이긴다)

**증상:**
- 다중 모듈 Maven에서 상위 모듈을 `install`한 **직후** 하위 모듈 빌드가 **이번 변경과 무관한 클래스**를 못 찾는다(`cannot find symbol`). 방금 install한 jar를 열어보면 클래스 구성이 다르다.
- **역방향(더 조용함)**: 내가 install한 뒤 **다른 워크트리**에서 상위 모듈 install 없이 하위만 빌드하면 **그쪽이** 깨진다 — 내 브랜치에서 지우거나 이름 바꾼 메서드를 그쪽 코드가 부른다.

**진짜 원인:** `~/.m2/repository`는 **머신 전역 하나**다. 고정 버전(비-SNAPSHOT) 같은 GAV로 install하면 **마지막에 쓴 쪽이 이긴다**. 워크트리 여러 개가 같은 `groupId:artifactId:version`을 쓰면 서로의 jar를 조용히 덮는다.

**실측(khnp cme-9.3.1, 2026-09-11):** 워크트리 5개가 `com.crinity:crinity-toc-core:9.3.1` 공유. 10:46 install → 10:48 다른 세션 install로 954 classes짜리 교체 → 하위 모듈 컴파일 실패 → 재install 후 950 classes(대상 클래스 포함) 확인하고 **곧바로** 하위 빌드해 해소. **같은 날 다른 워크트리에서 재발**(그 세션은 `attachtransferlog` 항목이 0건) — 우연이 아니다.

**회피:**
- 상위 모듈 install **직후 이번 변경의 식별 표지**(새 클래스·새 메서드)가 jar에 있는지 확인하고 **즉시** 하위 모듈을 빌드한다(`jar tf <jar> | grep <클래스>`, 또는 클래스 파일에서 메서드명 문자열). **사이에 다른 작업을 끼우지 않는다** — 창을 좁히는 것이 유일한 회피다.
- 하위 모듈 빌드가 **무관한 클래스 부재**로 깨지면 소스 결함보다 **공유 jar 덮어쓰기를 먼저 의심**한다. 재install 1회로 해소되면 "환경" 분류이지 소스 결함이 아니다.
- install을 했으면 **"공유 jar가 이 브랜치 버전이 됐다"를 기록·통지**한다 — 같은 GAV를 쓰는 다른 워크트리는 자기 상위 모듈을 먼저 install해야 한다.
- 워크트리별 `-Dmaven.repo.local` 격리는 원리상 답이지만 오프라인(`-o`) 의존성 사본 비용·디스크 용량이 **미검증**.

**DB와의 차이:** DB는 "순차만 답"이고 `~/.m2`는 **"install 직후 확인 + 즉시 사용"으로 창을 좁힐 수 있다.** 같은 층이지만 회피 폭이 다르다.

---

**공통 교훈:** 착수 게이트(toplevel/branch 확인)는 **잘못된 클론** 사고는 막지만 **정상 세션끼리의 동시 실행**은 못 막는다. 의미가 독립이어도 자원이 독립이 아니면 순차다 — `orchestrator.md ## 핵심 규칙`의 자원 경합 축이 이 페이지를 가리킨다. 실행 절차는 `agents/tester/tester-backend.md ## 공유 아티팩트 저장소`.
